## Root cause (confirmed by probe)

- `librecomp/include/librecomp/addresses.hpp`:
  - `mem_size = 512ULL*1024ULL*1024ULL` = **512 MiB**
  - `allocation_size = 4096ULL*1024ULL*1024ULL` = **4 GiB**
- `recomp::start` does `mmap(4GiB, PROT_NONE)` then `mprotect(rdram, 512MiB, RW)`.
  Everything beyond 512 MiB stays `PROT_NONE`.
- Recompiled `MEM_W(offset, reg)` for a 64-bit reg: `rdram + (reg+offset) - 0x80000000`.
  - SI regs `0xA4800000..0xA4800018` → offset `~0x24800000` = **580 MiB** (faults).
  - PI regs `0xA4600000+` → offset ~0x26000000 (faults).
  - VI regs `0x04400000..` → offset ~0xFC400000 (also out of range).
- Debug probe added to `tools/N64ModernRuntime/librecomp/src/recomp.cpp`
  (still in place): prints `mmap(4294967296) -> 0x...`, `mprotect(536870912)
  -> 0 (errno 2)`.

## The real issue: verbatim libultra

- The ELF symbols are generic (`func_80094860` = `osCreateThread`, etc.), so
  N64Recomp's `reimplemented_funcs` name matching never fired. The ROM's
  libultra is recompiled verbatim; runtime-native `osXxx_recomp` functions are
  never invoked.
- Consequences: the game's `osViSetMode`/`osContInit`/`osPiStartDma`/... write
  to the rdram mapping instead of driving runtime services. Even if the SIGBUS
  is papered over (enlarge the RW region), the game will hang waiting for VI/SI
  responses that never come.

## How the runtime is supposed to hook libultra

- `N64Recomp` renames functions whose ELF symbol matches a name in
  `N64Recomp::reimplemented_funcs` (`tools/N64Recomp/src/symbol_lists.cpp`)
  to `<name>_recomp` and marks them `reimplemented`/`ignored`. Calls to them
  then hit the runtime's `osXxx_recomp` implementations
  (`librecomp/src/ultra_translation.cpp`, `vi.cpp`, `cont.cpp`, ...).
- That only works when the ELF has libultra **names**. OB64's ELF does not
  (splat `libultra_symbols: True` produced no names for this game).

## Fix options for the next session (in order of preference)

1. **Name the libultra symbols in the ELF** (cleanest, matches Zelda64Recomp):
   - Research why `libultra_symbols: True` didn't populate names for OB64
     (likely spimdisasm's N64LibultraSyms table doesn't cover this libultra
     revision). Add symbol_addrs entries for the libultra functions
     (`osCreateThread` etc. at their ROM addresses), re-splat, rebuild ELF,
     re-run `make recomp`. Then runtime replacement kicks in automatically.
   - Requires knowing each libultra function's address in OB64's ROM.
2. **Address-based redirection in the app**: keep the verbatim recomp, but map
   the known hardware-touching ROM function addresses to the runtime's
   `osXxx_recomp` functions. Caveat: verbatim code calls `func_800xxxxx`
   directly (not `get_function`), so `add_loaded_function` alone won't
   intercept; this needs a call-site-level mechanism.
3. **Intercept MMIO in the MEM macros / rdram layer** (hacky but quick):
   - Enlarge the RW region so MMIO offsets don't fault, then route
     SI/VI/PI/SP/DP/AI register reads/writes to ultramodern/librecomp's
     emulation. ultramodern exposes `ViRegs*` via
     `ultramodern::renderer::get_vi_regs()`.
4. **Skip the game's libultra entirely**: remove it from the recompiled ELF
   (splat segment split) and let the runtime provide everything. Risky (custom
   libultra internals the game pokes directly).
