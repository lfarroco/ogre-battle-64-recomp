## 2. Why the config files carry `../` paths

splat resolves a config's paths against that config's own directory
(`splat/util/options.py:402`, `base_path = config_paths[0].parent / base_path`).
N64Recomp does the same for `elf_path`, `rom_file_path`, `output_func_path`,
`relocatable_sections_path` and `symbols_file_path`
(`tools/N64Recomp/src/config.cpp:296`, `concat_if_not_empty`). RSPRecomp does the
same for `rom_file_path` and `output_file_path`
(`tools/N64Recomp/RSPRecomp/src/rsp_recomp.cpp:723`). The moves therefore
required path edits inside the configs, not only in the callers:

- `config/config.toml`: `../RecompiledFuncs`, `../build/ogrebattle64.elf`,
  `../assets/ogre64.z64`, `symbols/relocatable_sections.txt`.
- `config/config.yaml`: `base_path: ..`, `symbol_addrs_path` and
  `reloc_addrs_path` point at `config/symbols/`, and
  `undefined_{syms,funcs}_auto_path` were added for the same directory (they were
  previously splat's `base_path` defaults).
- `config/rsp-*.toml`: `../assets/ogre64.z64`, `../RspFuncs/<name>.cpp`.
- `config/banks/config-bank<U>.yaml`: `base_path: ../..`, plus explicit
  `symbol_addrs_path` and `reloc_addrs_path` entries. Both were previously found
  as splat's `base_path` defaults at the root.
- `config/banks/config-bank<U>.toml`: `../../build/bank<U>.elf`,
  `../../assets/ogre64.z64`, `../../Bank<U>Funcs`.

`reloc_addrs.txt` holds six entries at ROM `0x1000..0x102C` (the boot header), so
it is inert for the bank units, whose first segment is a `bin` covering that ROM.
The explicit `reloc_addrs_path` keeps the units' input set equal to the old one.
Adding it changed no byte: a full `make bank-recomp` with and without it produced
identical `Bank*Funcs/` and `build/bank*.elf` (SHA-256 manifest, 186 files).

## 4. A pre-existing inconsistency this session exposed

The tree's `build/bank<B..L>.elf` were not what their own configs produce. Unit
B: the file in the tree hashed `620652ce…`; re-splitting from the same
`HEAD` config and re-linking hashed `b586bf5d…`. The split output (asm, `.ld`,
`undefined_*.txt`, `extra_syms.txt`) is byte-identical either way, so the stale
ELFs were linked from an earlier config content and `make` never relinked them.

Consequence: the `Bank<B..L>Funcs/` in the tree before this session were
generated from those stale ELFs. Session 87c already recorded the related
observation that 26 `Bank{B..L}Funcs/` files differ from a fresh regeneration in
`recomp_trace_return` depth constants only. This session's moves forced the
relink, so `Bank{B..L}Funcs/` now match a fresh regeneration. No source or config
content changed to cause this; do not read it as a regression from the move.
